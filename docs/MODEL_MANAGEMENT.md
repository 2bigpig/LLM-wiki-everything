# 模型连接与用途管理

everything 使用 LangChain 独立厂商适配包，模型配置存 PostgreSQL；现有 API/Worker、LangGraph、队列和模型容器保持原架构。

## 首次准备与旧配置升级

先停止正在运行的 API/Worker。数据库和模型容器保持运行。在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup-local.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\start-backend.ps1 -Service migrate
powershell -ExecutionPolicy Bypass -File .\scripts\prepare-model-settings.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\start-backend.ps1
```

准备入口幂等：保留现有数据库密码，缺少时生成 `MODEL_CREDENTIAL_KEY`，保存在根目录 `.env`，不在终端显示值。开发阶段直接打开设置页即可配置模型，不再生成或校验临时共享口令。不要将 `.env` 发给他人。

原 YAML 中 LLM 地址、模型、超时及输出额度配合旧 `LLM_API_KEY` 导入默认连接；成功才从文件移除旧密钥键。没有旧密钥时正常初始化。若密钥存在却缺少模型名称，准备会停止并保留原文件。备份 `.env.backup.models.*` 同样含敏感数据，受 Git 和 Docker 忽略。

凭据用 Fernet 加密保存 PostgreSQL，解密主密钥只在 `.env`。备份数据库时必须另外保管对应 `.env`；丢失主密钥无法恢复厂商凭据。密钥损坏时恢复原值，不能随意生成新值覆盖。

数据库升级到 `0003`，新增模型连接、修订、偏好、探测、向量空间及来源向量表；旧来源与引用 ID 不变，原 BGE 向量导入默认空间。降级使用升级前数据库备份，迁移不会自动删除模型数据。

## 配置在哪里修改

- `config.yaml`：监听、Docker、目录、预算上限、初始参数和厂商预设。更改部署参数需重启相应进程；模型容器参数仍由 YAML 管理。
- 设置页／PostgreSQL：LLM 连接地址、模型 ID、密钥、启停、超时、输出上限和阶段分配。Embedding 与 OCR 为项目固定技术栈，不提供用户替换入口。
- `.env`：数据库密码和模型凭据主密钥。`LLM_API_KEY` 仅用于旧配置导入；运行调用不再使用它覆盖数据库配置。

准备脚本生成或修改主密钥后，需要重启 API/Worker 一次。前端始终请求项目后端，不直接调用厂商。

## 页面操作

### 首屏快速接入

打开“设置与用量”，直接选择厂商、填写厂商 API Key 与模型 ID，再点击“测试并启用”。开发阶段不设置临时访问口令，用户登录与 RBAC 留到下一步统一实现；模型配置中的 API Key 只用于调用厂商。

普通厂商自动带出协议和地址，可点“修改地址”；自定义服务和 Azure 直接展示地址输入，Azure 还需填写 API 版本。Ollama、LM Studio 及自定义免密服务可留空 API Key，模型 ID 必须与实际服务一致。

API Key 输入框右侧的眼睛按钮可显示或隐藏本次输入；清空、保存或关闭后恢复隐藏。已保存的厂商密钥仍不从服务端回显。当前模型 ID 支持手填，高级设置的“读取模型列表”会调用所选连接的模型发现接口，首屏尚未接入社区模型目录。

按钮依次保存连接、保存模型、测试 JSON、启用默认模型。测试只发送固定文本，可能产生费用；测试失败保留已保存对象，不替换原默认。测试通过但用途保存失败时，再次点击只继续保存用途，不重复测试；修改模型或密钥后需重新测试。

保存响应因网络中断丢失时，先点击“核对保存结果”，不会自动重复创建。模型启用后首屏显示默认模型和测试状态，可点“更换模型”重新配置；原来单独指定的阶段用途不变。高级功能统一从“高级设置”展开。

### 高级管理

1. 添加 LLM 连接，选择厂商预设，确认地域、标准 API 地址及对应密钥。国内智谱与国际 Z.AI 是不同连接；不要混用密钥。Azure 地址填写资源端点，模型 ID 填部署名，并配置 API 版本。
2. 添加 LLM 模型。可读取模型列表，也可手动填模型 ID／火山方舟 endpoint ID。列表读取失败不代表该模型不能调用。预设不承诺每个模型支持全部功能。
3. 主动测试调用或 JSON。测试只使用固定测试文本，不发送收藏正文；可能产生费用，调用和用量记录可查。未测试与测试失败分别展示。
4. 分配默认模型，按需覆写分析、关联、Wiki 和深层回顾；分析分组与合并共用分析绑定。日常站内回顾默认不调用模型。
5. 复制连接只复制公开配置，需要重新填写密钥。停用连接立即阻止后续调用，在途请求可能完成；历史记录仍保留。

当前开发接口直接访问，已移除临时口令、解锁区域及会话接口。旧 `.env` 中的 `API_TOKEN` 仅为兼容保留，不再影响访问，也不需要手动删除；正式访问控制由后续登录与 RBAC 实现。表单中的厂商密钥保存后不回传、不进入浏览器持久化存储。

## 参数修订、重试与预算

### 设置页字段说明

- **模型用量**显示本月 Tokens 与 `config.yaml` 中的项目额度，不是厂商余额或货币账单。异常请求可能已产生费用，最近调用记录可辅助排查。
- **当前整理能力**显示配置是否启用，不代表远程服务健康或已完成能力测试。
- **连接**管理协议、服务地址和厂商 API Key；**模型**管理具体模型 ID 及调用参数，同一连接可以添加多个模型。
- **厂商预设**提供默认地址和协议；**连接名称**与**模型名称**供自己辨认，**模型 ID**必须填写实际模型名或部署 ID。更换地址或协议需要重新填写密钥，本地免密连接可显式留空。
- 用户只配置 **LLM**，负责分析和生成；Embedding 与 OCR 使用项目内置模型，无需选择类型。
- **超时**限制单次调用等待时间，**最大输出 Tokens**限制单次回复长度，两者都不是月度额度。
- **Temperature**控制随机性，留空使用厂商默认；**思考模式**要求模型支持对应推理参数；**Azure API 版本**只用于 Azure 协议。
- **读取模型列表**失败时仍可手填 ID；**测试调用**检查基础响应，**测试 JSON**检查结构化输出。测试可能产生费用，配置保存本身不会联网测试。
- **用途分配**中，分析与综合提取摘要、要点和主题，内容关联解释新旧资料联系，Wiki 生成维护知识页，深层回顾按需生成深入解释。未覆写的阶段使用默认模型；基础每日回顾不额外调用 LLM。
- **内置处理能力**：Embedding 使用 BGE-M3（1024 维），OCR 使用 PaddleOCR，页面只显示状态，不提供模型、连接或索引空间切换。

日常最简配置路径：选择厂商、填写 API Key 和模型 ID → 测试并启用。LLM 多连接、用途覆写和详细调用记录在“高级设置”中。

### 配置生效与用量

修改模型参数产生不可变修订，新任务固定各阶段修订；自动重试和“继续处理”沿用已有修订，主动“重新分析”采用当前配置。原先未配置的阶段允许首次补配恢复，不改动已固定阶段。

同一目标的 API Key 可轮换，后续请求读取新密钥。修改地址或协议必须显式替换密钥（免密服务填空），原任务停止使用旧目标，需要重新保存模型并重新分析。不会携带密钥跨地址重定向。

各 SDK 自动重试关闭，任务重试由现有队列管理，不自动跨厂商 fallback。调用记录包含连接、修订、用途和实际或保守预留用量，JSON 校验失败也记录已发生用量。厂商不返回 usage 时保留估算，Token 额度不是货币账单。云端向量及测试计入总额度，本地 BGE 记录调用但不计云端 Token。

兼容协议的思考参数按厂商约定传递，Claude/Google 使用各自协议。不同模型参数约束不同，不支持时明确失败，不静默删除参数；Claude 启用思考时输出上限需大于 1024。

## LLM 优惠时段调度

在“设置与用量”的“LLM 执行时间”中开启每日优惠时段，填写开始、结束和 IANA 时区（默认 `Asia/Shanghai`）。支持跨午夜，例如 `22:00–06:00`。默认关闭调度、立即处理；页面修改存 PostgreSQL，即时生效，无需重启。YAML 中的 `model_management.schedule_defaults` 只提供首次默认值。

结束策略可选：

- **本批全部完成（默认）**：时段内进入本批的待办和直接后续解释继续完成，可能跨入非优惠时段；结束后新提交的任务等待下一次。
- **时段外等待**：结束后停止发起新的后台 LLM 请求；在途请求正常完成，后续步骤保留检查点，等下一次时段继续。

策略统一覆盖分析（包括分段与综合）、内容关联、Wiki 和深层回顾。资料保存、网页读取、OCR、ASR、BGE 索引以及不调用模型的事实回顾照常运行。手动模型测试立即执行，仍计入原预算。系统只控制请求发起时机，实际价格以厂商时区及计费规则为准。

等待显示为“等待执行时段”，可查看预计继续时间或停止任务；等待不算失败、不消耗重试、不预留 Tokens。队列与检查点持久化，服务重启后恢复；错过整个时段则等下一个，不在启动时追补过去批次。已入批且选择全部完成的任务可以在重启后继续。

切换结束策略会在后续请求前生效；关闭调度会放行等待任务。不会自动更换任务固定的模型修订，也不会自动跨厂商调用。

接口为 `GET/PUT /api/model-settings/schedule`，包含 `enabled`、`start`、`end`、`timezone`、`end_policy`（`finish_batch` 或 `wait_next_window`）。返回当前是否在时段及下次开始时间；`/api/runs` 的 `scheduled_for` 为 UTC 时间，便于页面展示。

## 内置检索与 OCR 服务

Embedding 使用 BGE-M3（1024 维），OCR 使用现有 PaddleOCR/PP-OCRv5 服务，由项目统一维护。用户只配置 LLM，不创建、编辑或停用内置模型连接，也不创建或切换向量空间；直接调用旧接口同样会收到明确的固定技术栈提示。

内部向量空间、分批补齐、来源版本与历史引用继续保留，不删除已有向量。新资料沿用内置空间索引，向量服务故障时搜索仍降级为关键词；系统部署参数继续由开发者通过公共 YAML 管理。

## 排错

- 管理页提示准备：执行准备脚本生成模型加密主密钥，重启后端后刷新页面。
- 解密失败：恢复对应主密钥，不要覆盖；检查是否用错了配置目录。
- 等待配置：检查默认／阶段绑定、模型与连接是否启用，以及目标地址是否修改后尚未重新保存模型。
- JSON 测试失败：更换支持 JSON 的模型，检查思考模式、输出长度和厂商支持范围。
- 读取列表失败：使用手动模型 ID；某些兼容服务没有 `/models`，Azure 的部署发现也可能需要额外权限。
- 向量失败：检查 BGE 容器与 Worker 是否运行，必要时由开发者检查固定服务部署；用户无需更换向量模型。
- 使用调用记录中的连接、修订和用途定位问题；终端/API/Worker 日志保留类型和请求 ID，不输出密钥和资料正文。
